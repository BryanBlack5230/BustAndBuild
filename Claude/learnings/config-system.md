# Config / Balance System (ConfigHub)

Replaces the old JSON `ConfigContainer` path for balance tuning. Built across the 2026-06-14 refactor — Phases 1/2/3/5 all landed (no remaining phases; the original spec `Claude/ConfigTask.md` was removed once done). Supersedes the "Config Pipeline" notes in [[events-and-services]].

## The Shape
- **`ConfigHub`** (`Infrastructure/Settings/ConfigHub.cs`, namespace `...Infrastructure.Settings`) — MonoBehaviour on the **Bootstrap scene**, the single editing surface. Renamed from `PrototypeConfigSetter` keeping the **same `.cs.meta` GUID** (`1e3bd763e9d74ef08c9bc9db98559d26`) so the scene component reference survived; `BootstrapInstaller` uses `[FormerlySerializedAs("_prototypeConfigSetter")]` to keep its field link. Bound in `BootstrapInstaller` as `AddSingleton(_configHub, typeof(ConfigHub))`.
- **`BlobContainer`** (`Infrastructure/Settings/BlobContainer.cs`) — the single baker. Ctor now takes only `ConfigHub` (dropped `ConfigContainer`). `BootstrapFlow.Start` calls `_blobContainer.Initialize()` after the load chain. `IDisposable`, disposes the persistent blob.
- **Delivery:** per-unit-type profiles → `TargetProfilesBlob`; flat scalar groups → `IComponentData` singletons, all pushed at bootstrap by `BlobContainer.Initialize()`.

## Profile SOs (two types, two stat blocks)
- `EnemyUnitProfile` / `AllyUnitProfile` (`_MonoWorld/Settings/Configs/`, **global namespace**, `[CreateAssetMenu "Game/Units/..."]`). Each carries its **typed enum** (`EnemyType` / `AllyType`) + a shared `[Serializable] TargetingProfile` struct + a `[Serializable] CombatProfile` struct, and implements `IUnitProfile` (`TypeValue`/`TypeLabel`/`Targeting`/`Combat`) so the hub + baker treat both uniformly.
- **`CombatProfile`** (Phase 2, in `TargetingProfile.cs`) — currently one field `IncomingDamageScale` (bounce/landing damage multiplier; ally assets 0.25, enemy 1.0). Baked into the SAME `TargetProfileBlob` (no parallel array) via `ConvertToStruct(Targeting, Combat)`. Consumed by `InAirCollisionJob.IncomingDamageScale(entity)` (faction → `EnemyUnitType`/`AllyUnitType` lookup → `blob.{Enemy,Ally}Profiles[(int)type].IncomingDamageScale`; faction-only `0.25/1.0` fallback when the blob is absent). **Unmapped blob slots seed `IncomingDamageScale = 1`** (`BlobContainer.NeutralSlot`) so a missing profile takes full damage, not zero.
- **Enum-slot baking contract:** `BlobContainer.BuildProfileArray` sizes each blob array to `Enum.GetValues(...).Length` and writes each profile at `array[(int)profile.Type]`. List order is irrelevant; missing types stay `default` (zeroed → detection radius 0 → never targets). `TargetScorerJob` still indexes `EnemyProfiles[(int)EnemyUnitType]`, so the contract must hold. `ConfigHub.OnValidate` warns on null/duplicate/missing types.
- Asset `.cs.meta` GUIDs are fixed in source: `EnemyUnitProfile` `b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7`, `AllyUnitProfile` `c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8`. 6 assets live in `Resources/Settings/UnitProfiles/` (Grunt/Tank/Rusher, Soldier/Archer/Mage).
- **Field-name bug fix (done):** authoring fields are `DetectionRadius` (m) / `ViewAngleDegrees`; `ConvertToStruct` is the ONLY place deriving `DetectionRadiusSq = r*r` (was double-squared) and `ViewAngleCos = cos(radians(deg*0.5))` (was treating cos as degrees). Authored `8`/`90` give identical behavior to before. `LowHealthBonus` was **dropped** (baked-but-never-read).

## Flat config singletons
`[Serializable] IComponentData` structs that **double as inline-serialized hub fields and ECS singletons** — one struct, no separate "data" DTO. Each exposes `static X Default` returning the pre-config literals.
- `BounceConfig` (`Components/`, global) — soft-land split, rebound, knock, bounce-damage factor, fallback min/max vel. Consumed by `InAirCollisionSystem` + `ScreenBounceSystem`. (Merges the task's separate InAirCollisionConfig/ScreenBounceConfig.)
- `BattleBrainConfig` (`Components/AI/`) — evade trigger ×mult, evade retreat dist, escape dwell secs. Consumed by `BattleBrainSystem`/`BrainDecisionJob` + `EnemyEscapeSystem`/`EnemyEscapeJob`.
- `SteeringConfig` (`Components/AI/`) — danger multiplier, look-ahead dist. Consumed by `Steer_ResolveSystem`.
- Systems read with `SystemAPI.TryGetSingleton<T>(out var c) ? c : T.Default` — the `Default` is non-zero/behavior-preserving (the sanctioned alternative to `default(T)`; see dots-new-system §6), so systems still run correctly in scenes that never went through bootstrap (e.g. isolated battle test scenes).

## Rebake (live editing)
`ConfigHub` has `[Inject] BlobContainer` and a `[Button] Rebake()` (`[DisableInEditorMode]`) → `_blobContainer.Initialize()`. Works because `Initialize()` is **find-or-create** per singleton (reuses the existing entity, `SetComponentData`) instead of always `CreateEntity` — re-running won't duplicate `Global_Target_Profiles` / `Config_*`. Reflex circular dep (BlobContainer ctor needs ConfigHub; ConfigHub `[Inject]` needs BlobContainer) is safe because ConfigHub is an **instance** binding.

## JSON is fully dead (Phase 3, done 2026-06-14)
`ConfigContainer`, `Config.json`, `ConfigGenerator` (BarkingBird → Generate Configs), and the dead `RuntimeConstants.Configs` class are **deleted**. `BlobConfigConverter` + `[BlobConfig]` were deleted earlier (Phase 1). Nothing reads JSON for config anymore.
- The last two consumers moved to SOs: **`CameraConfigSO`** (`BattleCameraMovement` → `CameraDragHandler`/`CameraBorderHandler`) and **`PowerHitConfigSO`** (`PowerHitController`). Both live in `_MonoWorld/Settings/Configs/` in the **global namespace** (matching their profile-SO siblings), `[CreateAssetMenu "Game/Config/..."]`, private `_camelCase [SerializeField]` + property getters. Their C# field-initializer defaults equal the retired `Config.json` values, so a freshly-created asset is behavior-identical (the old `borderPushCurve` key0 `inTangent=3` was unused — `AnimationCurve.EaseInOut` matches).
- **Wiring:** the two SOs are referenced from `ConfigHub` (`Camera`/`PowerHit`, `[InlineEditor]`) and bound **as their own types** in `BootstrapInstaller.InstallHubConfigs` (NOT via the hub — consumers depend on exactly what they need), with `InvalidOperationException` null-guards mirroring `TrajectoryPredictorSettings`. Bootstrap scope is an ancestor of the battle scope, so the battle-scope consumers resolve them across scopes. Unlike the flat ECS singletons, these are plain Mono-world SOs — **not** baked by `BlobContainer`, **not** rebakeable; edits apply on next play (no live Rebake).
- `DayNightSetting`'s TODO now points at the ConfigHub (daylight tuning is a candidate to migrate next; not done). *(Done 2026-06-14 — see below.)*

## Throw + Daylight onto the hub (2026-06-14)
Two more scene-bound MonoBehaviours folded into the hub flow:
- **`DaylightConfigSO`** (Configs/, global ns) — `DayLength`/`SunDownDuration`/`IsLooping`. Replaces the World-scene **`DayNightSetting`** MonoBehaviour (deleted). Referenced from the hub, bound in `BootstrapInstaller`, injected into `DayNightCycle` (World scope → resolves the bootstrap-scoped SO via the SetParent chain — see [[di-architecture]]). Defaults (60/3/false) match the old scene values.
- **`ThrowConfigSO`** (Configs/, global ns) — `ThrowScale`/`ThrowThreshold`/`MinMaxVelocity`/velocity-power curve/`Gravity` (`[MinMaxSlider]` kept via Odin). Replaces the config half of the Bootstrap-scene **`ThrowSettingsSetter`**. Defaults match the old scene overrides (`ThrowScale 0.1`, `Gravity 30`, curve EaseInOut). Injected into `GrabbingInteractor` + `ThrowTrajectoryPredictor`.
- **Split of the old `ThrowSettingsSetter`** (full hub flow): config → `ThrowConfigSO`; the `ThrowVelocitySettings` ECS singleton (64 curve samples + min/max) → **baked by `BlobContainer`** at bootstrap + Rebake (drops the old per-frame velocity re-sync — `BlobContainer.BuildThrowVelocitySettings`); the runtime piece → renamed **GUID-preserving** to `ThrowDebugTracker` (slim `IGameUpdateListener`: inspector readouts + `OnThrow` + per-frame gravity apply). `BootstrapInstaller` uses `[FormerlySerializedAs("_throwSettingsSetter")]`; `GrabbingInteractor.Release` now calls `_throwDebugTracker.OnThrow`. `BootstrapFlow` no longer calls `Initialize()` on it (the tracker lazy-inits in `OnUpdate`); the `ThrowVelocitySettings` bake rides on `BlobContainer.Initialize()`.
- **Gravity caveat:** gravity application stays a per-frame write to `PhysicsStep` in `ThrowDebugTracker` (NOT a BlobContainer bake) because `PhysicsStep` is authored in the battle ECS subscene and only appears once that scene loads — a bootstrap-only bake would regress gravity to the physics default until a manual Rebake. So the SO's `Gravity` is live-tunable; its curve/min-max need a Rebake.

## Authoring values onto the hub (Phase 5, done 2026-06-14)
The hub now owns per-type **authoring-script stats** too (`EnemyAuthoring`/`AllyAuthoring`/`BeaconAuthoring`/`WallSectionAuthoring`). Key wrinkle that drove the design: **Bakers run at subscene-bake time with no DI/hub/runtime-singleton access** — they can only read the authoring's fields + referenced SOs (call `DependsOn(so)` so edits re-bake). So delivery is **bake-time** (the Baker reads a profile SO into the prefab), **not** a runtime blob.
- **Why bake-time, not blob:** unit stats are baked-once-then-mutated (health ticks down), so a live Rebake adds no value — you wouldn't re-stamp a wounded unit. Editing a profile SO re-bakes the subscene (edit-time). `BlobContainer` is **untouched** by Phase 5.
- **`UnitStats`** (`Configs/`, global ns) — 17-field per-type block (move/combat/bounce/steering: `MoveSpeed`,`TurnSpeed`,`StoppingDistance`,`Health`,`AttackDamage`,`AttackCooldown`,`AttackRange`,`BounceBaseDamage`,`BounceMultiplier`,`BounceElasticity`,`AgentSize`,`DangerWeight`,`SurroundRadius`,`VisionDistance`,`ScanInterval`,`ObstacleLayer`(LayerMask),`ObstacleDangerCurve`(Curve)). `EnemyDefault`/`AllyDefault` statics seed from the EnemyTest/AllyTest prefabs (the no-profile fallback — note these diverge from the old C# field defaults: ally `MoveSpeed 2`, enemy curve `Quadratic` vs ally `Quadruple`, both `TurnSpeed 13`/`AgentSize 0.5`/`SurroundRadius 12`/`VisionDistance 5`/`ScanInterval 1`/`ObstacleLayer 512`). Added to `IUnitProfile` (`Stats`).
- **The profile SO now carries TWO consumption flows:** `Targeting`/`Combat` → live `TargetProfilesBlob` (runtime, Rebake-able); `Stats` (+ enemy `Drops`) → bake-time into the prefab. Same asset, different timing. This is intentional, not a smell.
- **Per-field overrides:** `UnitStatOverrides` (one `OptionalFloat`/`OptionalLayerMask`/`OptionalCurve` per field; `Apply(in UnitStats)` merges) sits on each unit authoring; structures get `OptionalFloat healthOverride`. `Optional*.Resolve(fallback)` = `Override ? Value : fallback`. Inline Odin (`[InlineProperty]` + shared `[HorizontalGroup("opt")]`).
- **Type wiring:** unit authoring keeps the `enemyType`/`allyType` enum **and** adds a `profile` SO ref (baker uses ref for stats, enum for the `EnemyUnitType`/`AllyUnitType` tag — resilient when profile unassigned; `OnValidate` warns on mismatch). Baker: `overrides.Apply(profile != null ? profile.Stats : UnitStats.{Enemy,Ally}Default)`, `if (profile != null) DependsOn(profile)`.
- **`BeaconConfigSO`/`WallSectionConfigSO`** (`Configs/`, global ns, `Game/Config/...`, private `_health`+getter, 6000/200) — no type enum, so one shared config each, referenced by the authoring (baker) + the hub (editing surface, `[InlineEditor]`, NOT DI-bound). Fixed `.cs.meta` GUIDs `d1e2f3a4b5c60718293a4b5c6d7e8f04`/`…f05`; assets at `Resources/Settings/{BeaconConfig,WallSectionConfig}.asset`.
- **`PickupConfigSO`** (`Configs/`, global ns, `Game/Config/Pickup Config`, `.cs.meta` `…f06`, asset `Resources/Settings/PickupConfig.asset`) — `PickupSpawnerAuthoring`'s 10 scalar tunables (lifetime/blink/pickup-radius/scatter/spawn-height/float/rest) as a `PickupTuning` struct (+ `Default`) with a per-field `PickupTuningOverrides` block on the authoring. The **prefab→`CurrencyType` mapping list stays on the authoring** (asset wiring baked via `GetEntity` into a `PickupPrefabRef` buffer — NOT moved to the SO). Same bake-time pattern: `overrides.Apply(config != null ? config.Tuning : PickupTuning.Default)` + `DependsOn(config)`.
- The 6 profile assets were pre-filled with `Stats`/`Drops` from the two prefabs (only one enemy + one ally prefab exist, so all 3 of each faction are seeded identically pending per-type tuning).

## Per-unit combat values (Phase 2, done 2026-06-14)
Split by *kind* of value, not lumped together:
- **`IncomingDamageScale` → config** (balance tunable). `CombatProfile` on the SO → `TargetProfileBlob` → `InAirCollisionJob` (see "Profile SOs" above). Replaced the inline `if (IsAlly) *= 0.25f` in `Landed`/`DoBounce`/`SoftLand`.
- **Screen-bounce half-extents → real collider** (geometric property, NOT config — avoids drift, and keeps `ScreenBounceSystem` free of blob/type-lookup plumbing). `PhysicsUtility.GetColliderHalfExtentsXY(in PhysicsCollider, float2 fallback)` is a new **Burst-friendly** helper returning the **local (unrotated) AABB** half-extents (sibling to the existing `GetEntityHalfExtentsXY`, which takes `EntityManager` + applies rotation — not Burst-safe). `ScreenBounceSystem` reads it via `ComponentLookup<PhysicsCollider>` per airborne entity, fallback `0.25×0.5`; the oriented-corner math is unchanged. **Not migrated:** ScreenBounce's separate `if (!isAlly)` zero-damage rule (different rule, out of scope).

## Hit-feedback, trajectory + pickup-magnet onto the hub (2026-06-15)
Closed the last gaps a config audit turned up — three more surfaces folded onto the hub, each picking the pattern that matches *how it's consumed*:
- **Hit-feedback profiles** (`FlashProfileSO`/`SquashProfileSO`/`PushProfileSO`, global ns, assets in `Resources/Settings/HitFeedback/`) — added as hub `[InlineEditor]` editing surfaces under `[Title("Hit Feedback")]`, **NOT DI-bound**. They're consumed **bake-time** by `HitFeedbackAuthoring`'s baker, which reads the authoring's *own* SO ref → `DamageFlashConfig`/`DamageSquashConfig`/`DamagePushConfig` on the prefab — identical to the Beacon/Wall/Pickup pattern. The hub field is a pure editing pointer at the same shared asset; `OnValidate` **warns** ("…unassigned on the hub editing surface") rather than throwing, because a null hub ref doesn't break baking (the prefab's authoring ref does the work). `BlobContainer` untouched.
- **`TrajectoryPredictorSettings`** — added a hub field and **moved its DI binding from `BattleGroundSceneInstaller` (battle scope) to `BootstrapInstaller.InstallHubConfigs` (bootstrap scope)**, sourced from the hub (`AddSingleton(_configHub.TrajectoryPredictor, typeof(TrajectoryPredictorSettings))` + `InvalidOperationException` guard). Removed the old battle-installer `[SerializeField]`/guard/binding (its serialized ref orphans harmlessly; dropped `using …Gameplay.Settings;` there, but **kept `using System;` — still needed for `IDisposable`**). Consumer `ThrowTrajectoryPredictor` stays battle-scope and resolves the SO up the parent chain — same cross-scope resolution as Camera/PowerHit. Hub is now the single source of truth. (The earlier note "null-guard pattern mirrors TrajectoryPredictorSettings in BattleGroundSceneInstaller" is now historical — that pattern lives in `BootstrapInstaller`.)
- **`PickupMagnetConfigSO`** (NEW, `Configs/`, global ns, `Game/Config/Pickup Magnet Config`, asset to be created under `Resources/Settings/`) — extracted `PickupMagnetController`'s `_magnetDuration`/`_magnetEase` (HUD fly-to-counter feel; PrimeTween `Ease`). Defaults `0.4`/`Ease.InCubic` match the old inline values. `PickupMagnetController` is a **scene MonoBehaviour in `2.World`** (Reflex GameObjectInjector, *not* a registered singleton) — extended its `[Inject] Construct(Wallet)` to `Construct(Wallet, PickupMagnetConfigSO)`. Bound at bootstrap from the hub; the World scope resolves it across the parent chain (Bootstrap is an ancestor), exactly as it already resolves `Wallet`. Old serialized feel values on the HUD object orphan harmlessly.
- **Pattern recap (what decides DI-bound vs editing-surface-only):** bake-time-via-authoring SOs (hit-feedback, Beacon/Wall/Pickup) → hub `[InlineEditor]` ref only, no DI, *warn* on null. Runtime-DI SOs (trajectory, pickup-magnet, Camera/PowerHit/Throw/Daylight) → hub ref **+** bound-from-hub at bootstrap, *throw* on null. Nothing here is blob-baked.
